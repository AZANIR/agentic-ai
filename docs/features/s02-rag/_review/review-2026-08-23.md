## How it was done

Both reviewers re-read the specification, the SAD and the ADRs themselves, with no retelling from
the author. Both were allowed to run the code and mutate it. Between them they applied **21
mutations** and returned **9 MAJOR, 8 MODERATE, 13 MINOR**.

This is the second stage in a row where an independent review finds, in code the author had
already declared finished and mutation-checked himself, mistakes in the same category: **a check
with the right verdict and too weak a statement**.

## What went from this into the PLAYBOOK

Seven lessons (§5). The most important is the one that repeated within this stage **twice, by
different mechanisms**: a test for "the forbidden thing did not get through" never replaces a test
for "the permitted thing arrived". Both times the leak check stayed green.

Second in weight is one about the instrument itself: the mutation harness reported "0 red" for six
mutations in a row, because the mutation broke the import and there were no `FAIL` lines in the
output at all. The instrument used to check whether a check is lying lied in exactly the same way.
