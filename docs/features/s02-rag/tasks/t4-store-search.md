# T4 — Індекс, косинус, top-k, поріг і фільтр доступу

## Why

Серце етапу. Порядок операцій тут — предмет [ADR-0002](../adr/0002-filter-by-access-level-before-top-k.md), а не деталь реалізації.

## What

`store.py`: індексація фрагментів, косинусна близькість, відбір top-k, поріг релевантності з конфігурації. **Фільтр за рівнем доступу застосовується ДО відбору top-k.** Зіпсовані документи називаються й пропускаються, база лишається робочою. Пошук пише у трейс оцінки й кількість відсіяного.

## Definition of Done

- [ ] Дослівне питання дає топ-1 = документ про повернення, з видимими оцінками
- [ ] Питання синонімами не знаходить — розрив зафіксовано перевіркою
- [ ] Нічого вище порога — повертається порожньо плюс найближчі оцінки й сам поріг
- [ ] Внутрішній документ не потрапляє у видачу покупцю
- [ ] **Дозволений документ не зникає з видачі** — доводить, що фільтр стоїть до відбору
- [ ] Порожній і надто короткий документи названі, решта бази шукається
- [ ] Три послідовні прогони дають ідентичний порядок
- [ ] Модуль ≤ 80 рядків виконуваного коду (spec §6)
- [ ] lint чистий

## Notes

Ліміт 80 рядків затісний: у модулі косинус, top-k, поріг і фільтр. При перевищенні фільтр виноситься окремим модулем, як гейт на етапі 1 — не роздувати ліміт ([sad §11](../sad.md)).
