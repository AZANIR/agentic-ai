## The main finding: the headline claim was untrue

The lesson opened like this:

> No version of CrewAI — from 0.1.0 to 1.15 — declares support for Python 3.14.

One command refutes it:

```
pip download crewai --no-deps
Successfully downloaded crewai-0.11.2
```

Old versions declare `>=3.10,<4.0` and install just fine. The `<3.14` bound starts at
**0.14.0**.

The worst part is not the inaccuracy itself but that `CHECKLIST.md` tells the reader to verify it
by hand — so the first conscientious check would have refuted the lesson.

**Fixed, and the precise wording turned out to be stronger than the imprecise one:** no version
**from 0.14.0** — that is, none in which `crewai.BaseLLM` and `crewai.tools.BaseTool` exist, the
two through which the stage feeds in its own client. The choice is this: **either a version that
installs and has nothing to plug the client into, or a version with the API you need that does not
install.** Both branches lead to "not evaluated", and that says more than a plain "does not install".

A stage whose thesis is "count it, do not assume" opened with an assumption.

## Three asserts that could not turn red

**AC-02 was a tautology for three implementations out of four.**

```python
ran = _counted_rows(rows)          # filters on exactly `not row.broken`
for row in ran:
    assert not row.broken          # ...and then asserts there is no broken
```

`_counted_rows` threw out from under the assert exactly those the assert was supposed to complain
about. The same root held AC-11 and AC-06: both reported `ok` while proving the property on two
rows out of four. Violations are now counted across **all** rows, and incomplete coverage is handed
back as a third state — `NOT EVALUATED` with the list of what went unproven.

**The search for a hand-rolled transport could not see dotted paths.**
`code_mentions(src, {"openai.openai"})` returns nothing even on a source that literally contains
`openai.OpenAI(...)`: the helper parses the AST and sees `Name.id` and `Attribute.attr`
**separately**. So an implementation could construct its own client and the assert stayed green —
and that is ADR-0007, the central condition for running offline.

Replacing it with a word search produced a false positive on `"openai/gpt-4o"` — a provider prefix
for someone else's wrapper, which constructs nothing. Now the AST parse looks for a **call** of the
form `openai.OpenAI(...)`, and beside it stands the mirror half: a planted source with a literal
constructor must be found.

**AC-12 proved nothing about the run key.** `extract(traces)` takes the default `by_trace_id`, so
the `case` field had no effect on grouping. Measured: two runs **without** the key yield the same
two trajectories. Both asserts were identities, and the comment beside them claimed the opposite.
Grouping now goes **by the run key itself**, and the trajectory keys are checked against the
implementation names.

## Three ways to break the stage for an obedient reader

**`model="fake"` was hardcoded.** A reader with a key configured gets a real client from
`get_client()` — and the very first `create(model="fake")` earns a refusal from the provider. The
stage fell over on scene one for exactly the person who had done stage 1 and done everything right.
Now it is `get_model()`.

**The banner lied when a key was present.** The literal `"[FakeLLM] The model is fake…"` was
printed unconditionally, and the check `output.startswith("[FakeLLM]")` was a tautology on that
same literal. Stage 8 already paid for this, and the wording of its record — "the banner behind the
flag lied" — repeated here word for word. Now it is `shared.llm.banner(client)`.

**`S09_ADK=1` reddened seventeen checks out of twenty-eight.** Two commands from the module
docstring gave the reader seventeen reds and the advice to get a Google account that his own code
**does not need**: `_model()` deliberately steers ADK away from Gemini to our client through
`LiteLlm`. The credentials gate contradicted its own implementation.

Fixed by three edits: credentials are no longer a condition (the package check remains); `demand()`
is called from the **demo**, not from the table build that the checks call too; the order of the
branches was brought in line with SAD §6 — the flag first, availability second. The last one
incidentally made reachable the documented line "the flag is off by default", which on any install
without `google-adk` never appeared at all.

## NFR-8 demanded something the manifest did not do

The spec required "framework versions **pinned** by a bound", while `pyproject.toml` carried floors
alone: `langgraph>=0.2`. The check whose docstring reads "AC-08, NFR-8" verified the presence of a
line **with a floor** — that is, it asserted the opposite of what the NFR requires.

Sharpest of all: `DECISION.md` teaches the reader this very flaw — "A floor-only pin will hand
whoever installs the stage a year from now an entirely different package".

Now it is `langgraph>=0.2,<2` and `crewai>=0.60,<2` — the third case of an upper bound in the file,
after s04 and s06 — and the check parses the `s09` block with a regex and demands the upper bound
specifically. The dead `langchain-openai` went out with it: no module of the stage imports it.

## The warm-up held the headline number and nothing guarded it

The invisible-lines column flickered between processes: 1975 in a fresh one, 1895 afterwards. The
warm-up fixed that — but **no check would have noticed it disappearing**. The reason is that all
twenty runs of the determinism check happen in **one** process, where the package is already
imported.

And the number turned out worse than expected: in a genuinely cold trace LangGraph executes
**13992** lines instead of 1895 — sevenfold. So the measured number means "the price of a run after
the import", and that is now said out loud.

A check was added that takes one fingerprint in a **subprocess** and compares it with the
fingerprint taken in memory.

## The lesson's numbers were tied down by disjunctions

```python
assert f"| {row.mine} |" in lesson or str(row.mine) in lesson
```

Measured: the strict half `"| 37 |"` is **absent** from the README — the table is aligned with
spaces. So the claim rested entirely on the right half, and that half was already guaranteed by the
neighbouring assert about module size. Put 137 in the table instead of 37 and the suite would have
stayed green, despite the docstring "the table's numbers are computed, not typed by hand".

The line is now normalized over whitespace and compared in full, with no `or`.

## The comparison was asymmetric by five lines

`via_langgraph.py` imported `ask` from `baseline.py`: the baseline carried those five lines inside
its 37, while LangGraph got them for free. The error leaned toward "the framework is cheaper" —
exactly the side the solution to exercise 3 warns about.

Now every implementation has its **own** model call, and the honest difference is **37 against
54** — seventeen lines, not twelve.

## A column four texts promised and that existed nowhere

`contract.py`, both READMEs and `CHECKLIST.md` called the number of model calls "a measured
column". It was not in the table, and `tally.calls` went nowhere.

The consequence is not cosmetic: `asked` was counted by text match, so an implementation that sends
the same contract prompt five times had an overhead of zero and was indistinguishable from a frugal
one. Five extra paid calls were invisible in **every** column there was.

The column was added. Along with it, `owned_texts` now credits contract text as a **substring**
too — otherwise a role framework that nests the prompt inside "Current Task: …" would have had the
whole contract counted as overhead. The longest match is taken, with a guard: the contract texts are
nested inside one another, and a sum would have counted them twice, making the overhead negative.

## The prose asserted the unmeasured in four places

The section "What this plan deliberately does not prove" named only ADK. CrewAI has not been run
either — and it is precisely the stage's main finding. The consequence was visible in the prose:

| Where | What was claimed | State |
|---|---|---|
| `via_crewai.py` | "What it costs. Tokens" — present tense | not measured |
| `run.py`, scene 5 | printed on every run under a table of zeros | not measured |
| `exercises.md` | "a row with a non-zero overhead **will appear** in the table" | nobody has seen it |
| `DECISION.md` | "a role framework takes it out in tokens" — as law | not measured |

All four were moved into the conditional; in `DECISION.md` the table rows are marked `MEASURED` /
`NOT MEASURED`. The exercise now says it plainly: **nobody knows what will be in the CrewAI row** —
it may well hold "contract violated" instead of numbers. Both outcomes are an outcome.

## The rest of what was fixed

- `_root` matching by prefix without a separator would have conflated `langgraph` and `langgraph_sdk`.
- `max(0, …)` in `overhead` was an unreachable branch pretending to be a guard — now an invariant.
- `_texts` checked the type of the outer element but not the inner one: `{"function": "a string"}`
  from a framework would have killed the run right at the provider boundary.
- The ADK privacy assert was true by construction (`… not in said or name in said`).
- The "prose places" probe wrote a file into the source tree.
- The AC-08 smoke knew only LangGraph — now it walks every available implementation.
- "My lines" were blanked for rows that could not be run, although they are measured from the
  source — restored.
- Selection rule 5 cited a column that does not confirm it.
- The `BUDGET` constant was read nowhere.
- The root `README.md` listed stage 8 as 30/14 when the actual figures are 31/15 — it had drifted
  before this stage even started.

## What stays unverified — deliberately

`sys.settrace` to other threads, the warm-up doubling the runs, the demo ceiling as a constant, and
two implementations that could not be run.
