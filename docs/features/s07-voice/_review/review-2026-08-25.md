# Review — s07-voice · 2026-08-25

**Verdict: CHANGES REQUESTED → everything fixed → PASS**

> Thirty-one findings from two independent reviewers, seven of them critical. Among them —
> **a live mode that had never once worked**, a p95 that hid the tail on roughly half of all
> sample sizes, a breakdown that billed the browser's time to the model, an exercise whose
> "reds" were `NameError` instead of `AssertionError`, and an acceptance criterion that never
> reached the code at all. There are now **44** checks (was 33), **37** of them on failure
> modes (was 25). Mutations: **16** (was 12).

## Scope

- The review was done by **two independent reviewers in clean context**, in parallel:
  - **stage 1** — tracing 18 criteria from §5 down to the check function, recomputing the NFRs
  - **stage 2** — conventions, edge cases, whether the checks have teeth, live mode, the teaching texts
- Both read the artefacts themselves and tested their hypotheses with runs.
- **Neither of them found the most expensive defect.** The first launch found it — see below.

## The main finding: live mode never worked

`create_app()` registered the socket like this:

```python
from __future__ import annotations          # annotations become strings
...
def create_app(*, real: bool = False):
    from fastapi import WebSocket           # the type lives ONLY here

    @app.websocket("/voice")
    async def voice(socket: WebSocket) -> None:
```

FastAPI resolves annotations in the module's **global** namespace. `WebSocket` is not there, so
the string `"WebSocket"` does not resolve — and instead of an error FastAPI does the clever thing:
it treats `socket` as an ordinary query parameter. Every connection was closed with code 1008
"Field required" **before** `accept()`.

```
WebSocketDisconnect code=1008
reason=[{'type':'missing','loc':['query','socket'],'msg':'Field required'}]
```

That is, the stage's page worked neither with real models nor with fake ones — from the day it was
written.

Both reviewers **read this file** and saw nothing; one even traced AC-07 down to `ws.py:61-97` and
called it "the path is broken" for a different reason. Reading does not run.

**Fixed** by setting the type after the function definition — and, above all, by the check
`check_the_socket_actually_runs_a_conversation`, which brings the application up and drives a full
conversation through it. Without fastapi it honestly says `NOT EVALUATED`; in the CI job with
extras the rule "nothing is left unverified" makes it mandatory.

A second layer of the same defect: the pipeline was started **on every 200-millisecond frame**.
Time to first audio is counted from the **end of the turn**, so while the person is speaking there
is nothing to measure. Frames now accumulate, and the pipeline starts on `{"end": true}` from the
page.

A third: `pip install -e ".[voice]"` brought in neither `fastapi` nor `uvicorn` — and the next line
of the instructions called `uvicorn`. An `s07` extra was added; a check reconciles that the named
packages exist and give what the next line calls.

## The measurement lied in three ways

**The consumer's time was billed to the model.** `Stopwatch.step()` measures from the previous
mark, and in a generator control belongs to the consumer between a `yield` and the next step.
Measured on a consumer that spends a second between chunks:

```
steps: [('recognition',120), ('model reply',250), ('synthesis',80),
        ('model reply',1250), ('synthesis',72), ('model reply',1250), ('synthesis',72)]
'model reply' in total: 2750        the model slept: 750
sum of steps: 3094                  total: 4094
```

The most expensive step became whichever one the browser thought longest after. The stage's
invariant — "the sum of the steps equals the total time" — was asserted **only for batch**; for
streaming there was no such assertion at all.

Fixed by ADR-0007: the breakdown has three terms, and the third equals zero. The check drives a
deliberately slow consumer and asserts **both** halves — that the sum reconciles and that the
model's step equals what the model actually slept. Without the second, the conservation law would
also be satisfied when the model is blamed for someone else's delay.

**p95 was rounded instead of taken by rank.** `int(round(0.95·n)) - 1` diverges from
`ceil(0.95·n)-1` on 95 of the first 200 sample sizes. Over thirty runs:

```
Distribution(runs=30, mean=480, p95=400, worst=1600)  tail_ratio 0.83
share of runs worse than p95: 6.7 %
```

`tail_ratio < 1` reads as "there is no tail". A module that exists precisely to expose the tail was
hiding it — and the check stood at a hundred runs, that is, at a lucky number where `round` and
`ceil` agree.

**`total = 0.0` on a partially consumed stream.** The very defect that `measure.py` describes as
already caught on `first_audio` ("`None`, not `0.0`. Zero is a wrong value"), left in the
neighbouring field of the same type. A breakdown read after the first chunk showed "total 0 ms"
next to a non-empty list of steps.

## Checks with no teeth — seven of them

| Check | Why it did not catch | Proved by |
|---|---|---|
| the microphone only after an action | `assert ... in after or ... in before` — the right half is true for any page with an event listener | hoisting `getUserMedia` to module level left it green |
| the session leaves no traces | `assert forbidden not in source or forbidden == "wav"` — a guard immobilised to fit its own code | `"wav"` is always in `page.html` |
| the same | `write_bytes` was in the list, `write_text` was not | the mutation "writes the transcription via `write_text`" passed straight through |
| the socket has no delays of its own | `... or "clock.sleep" in socket` — `clock.sleep` was always in the file | `time.sleep(0.5)` did not turn it red |
| a missing model | `absent is None or absent == MISSING` — true always | the "the models are there" branch ran nowhere, and it was the broken one |
| twenty runs give one number | a pure function over a deterministic counter | it could not observe the flicker NFR-6 exists against |
| the pipeline does not read the system clock | a grep over three names | `datetime.now()`, `time.time_ns()` walked through |

Each one was fixed. The microphone — by positional inclusion in the body of `start()`; the storage
— by a list with no exceptions plus `write_text`; the delays — by an AST parse; the missing model —
by a parameter carrying a list of modules, so both branches run; determinism — by two concurrent
streams instead of twenty sequential ones; the clock — by parsing the **imports** instead of a list
of words.

## The teaching texts contradicted the code

**Exercise 5 did not compile.** The mutation substituted `CHUNKS_SENTINEL`, which does not exist in
the repository. All five "reds" were `NameError`:

```
FAIL  stream: time to first audio is at least twice as low as the batch one
--- NameError: name 'CHUNKS_SENTINEL' is not defined
```

Not a single assertion was reached, while the prose claimed a mechanism that never happened. This
is a word-for-word repeat of two lessons in `PLAYBOOK.md §5`, written down earlier by this very
repository.

Replaced with `enumerate(list(think_chunks(...)))` — one `list()` call, which turns streaming into
batch. It compiles, breaks exactly the property the prose talks about, and it is the most common
mistake in real code.

**`mutate.py s07 --expect` was red: DIVERGENCES 3.** In all three cases the extra red came from
`check_the_lesson_numbers_match_the_measurements` — a check about the **prose**, which recomputed
numbers from already-broken code. `require_intact_source` had been applied only to the line-count
check. Now it covers all six modules it measures.

**"The ratio falls from 3.5x to 1.6x"** — measured 1.69, that is 1.7. Fixed; the same number to two
decimals is now named in the checklist, because that is what the reader will see in the message.

**"Wasted work, named in the trace"** — there was no trace in the stage at all.

## AC-11 did not exist in the code

`grep -rl shared.trace stages/s07_voice` → zero files, against 4/2/4/2/2/3 at stages 1–6.
`CONVENTIONS.md` requires a trace **from stage 1**; `sad.md` drew `Rel(pipe, trace)`; `DECISION.md`
promised wasted work "in the trace". The check bearing AC-11's name asserted that `ws.py` contains
the line `from stages.s07_voice.pipeline import`.

Fixed by ADR-0008: the tracer is an optional parameter with a null object by default. The check
reconciles **the numbers of both mechanisms**, and the demo's seventh scene prints the
reconciliation. Stage 8 gets input data it would not otherwise have had.

While we were there: `sad.md` drew `Rel(pipe, llm, "Answer")` — the pipeline never called
`shared/llm.py` once. The diagram was fixed, and §5 now says **why** it is not there.

## AC-04: not a single run took place

The criterion says "a hundred runs on the same data **with a spread of latencies**". The
distribution was assembled from the literals `[400.0] * 90 + [1600.0] * 10`, and the demo printed
"runs: 100" for a list typed in by hand — on a stage whose thesis is "you can only optimise what
you have measured".

The fake clock gives no spread **by construction**, and that is its virtue. So the spread is now
introduced by the model: `latency(run)` — a pure function of the run index, a two-tier tail. A
hundred real runs give a mean of 1859 ms, p95 of 3824 ms and a worst of 6824 ms; a repeat run gives
the same hundred numbers.

A single tier would have given a p95 equal to the worst — and the difference between "almost the
worst" and "the worst" would have disappeared exactly where the stage shows it.

## The rest of what was fixed

- **`synchronous()` and `prefetched()` measured different quantities under one name.** The
  synchronous path did not sleep the thinking time, so a naive comparison of two `.millis` showed
  prefetch **slower** by 250 ms. Both consumers stitched the difference in from outside by hand.
- **The discarded prefetch waited on a tool** that was declared wasted work one line below. Both
  call points were picked (500 against 600) so that the difference was not visible.
- **An empty model reply gave "to first audio: 0 ms"** — the best possible latency for a run with
  no audio in it.
- **The page:** the microphone was not released on an error after permission was granted, and the
  button stayed disabled forever; there was no `onclose`/`onerror`, so the indicator showed intent
  rather than state; the `kind === "audio"` branch was unreachable, and `message.note` wiped the
  verdict on every breakdown; the table drew repeated step names with no total row.
- **`RealClock.sleep` blocked the event loop** — two conversations serialised. The pipeline step now
  goes into a thread.
- **`run.py --real` did not pass the clock into the scenes** — the flag changed only the banner.
- **`pipeline.py`'s docstring named types the functions do not return** (`-> Spoken`,
  `-> Iterator` instead of `Reply` and `Stream`) — in exactly the place where ADR-0003 builds a
  lesson on "the difference is visible in the type".
- **`Stream.chunks` handed back the tail after a partial pass** — a silent half of the answer.
- **The README said "three checks"** where there are four.
- **The page's numbers could not match the run:** the duration was derived from the length of the
  **compressed** opus (`len(chunk)/32_000` → 25 ms instead of 200). The page now names the frame
  duration itself, and its promise has been changed to an honest one: what matches is the
  **structure** of the breakdown.

## What stays unverified — deliberately

- **AC-07** (`NOT EVALUATED`): sound on a real microphone with real models. The author has neither
  model weights nor a microphone. The socket is now started by a check (AC-07c) — with no sound,
  but with a full conversation; what stays unverified is exactly the sound.
- **`real.py`** is written but not executed. The stage's weakest point, named in both READMEs, in
  `sad.md` §11 and in the file's own docstring.
