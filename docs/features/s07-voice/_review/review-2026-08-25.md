## Головна знахідка: живий режим не працював ніколи

`create_app()` реєстрував сокет так:

```python
from __future__ import annotations          # анотації стають рядками
...
def create_app(*, real: bool = False):
    from fastapi import WebSocket           # тип живе ЛИШЕ тут

    @app.websocket("/voice")
    async def voice(socket: WebSocket) -> None:
```

FastAPI розвʼязує анотації в **глобальному** просторі модуля. Там `WebSocket` немає, тож рядок
`"WebSocket"` не розвʼязується — і замість помилки FastAPI робить розумну річ: вважає `socket`
звичайним query-параметром. Кожне зʼєднання закривалося з кодом 1008 «Field required» **до**
`accept()`.

```
WebSocketDisconnect code=1008
reason=[{'type':'missing','loc':['query','socket'],'msg':'Field required'}]
```

Тобто сторінка етапу не працювала ані зі справжніми моделями, ані з підробленими — з дня, коли
її написали.

Обидва рев'юери **прочитали цей файл** і не побачили нічого; один навіть простежив AC-07 до
`ws.py:61-97` і назвав його «шлях зламано» з іншої причини. Читання не запускає.

**Виправлено** проставлянням типу після визначення функції — і, головне, перевіркою
`check_the_socket_actually_runs_a_conversation`, яка піднімає застосунок і проводить крізь
нього повну розмову. Без fastapi вона чесно каже `НЕ ПЕРЕВІРЕНО`; у CI-роботі з extras
правило «нічого не лишається неперевіреним» робить її обовʼязковою.

Другий шар тієї самої вади: конвеєр запускався **на кожен 200-мілісекундний кадр**. Час до
першого звуку рахується від **кінця репліки**, тож поки людина говорить, міряти нема чого.
Кадри тепер накопичуються, а конвеєр стартує на `{"end": true}` від сторінки.

Третій: `pip install -e ".[voice]"` не приносив ані `fastapi`, ані `uvicorn` — наступний рядок
інструкції кликав `uvicorn`. Додано extra `s07`; перевірка звіряє, що названі пакети існують і
дають те, що кличе наступний рядок.

## Вимірювання брехало трьома способами

**Час споживача приписувався моделі.** `Stopwatch.step()` міряє від попередньої мітки, а в
генераторі між `yield` і наступним кроком керування має споживач. Заміряно на споживачі, що
витрачає секунду між фрагментами:

```
кроки: [('розпізнавання',120), ('відповідь моделі',250), ('синтез',80),
        ('відповідь моделі',1250), ('синтез',72), ('відповідь моделі',1250), ('синтез',72)]
'відповідь моделі' у сумі: 2750     модель спала: 750
сума кроків: 3094                   total: 4094
```

Найдорожчим кроком ставав той, після якого найдовше думав браузер. Інваріант етапу — «сума
кроків дорівнює загальному часу» — стверджувався **лише для батчу**; для стрімінгу такого
ассерту не було взагалі.

Виправлено ADR-0007: розклад має три доданки, і третій дорівнює нулю. Перевірка ганяє навмисно
повільного споживача й стверджує **обидві** половини — що сума сходиться і що крок моделі
дорівнює тому, скільки модель спала. Без другої закон збереження задовольнявся б і тоді, коли
модель звинувачують у чужій затримці.

**p95 округлювався замість брати ранг.** `int(round(0.95·n)) - 1` розходиться з `ceil(0.95·n)-1`
на 95 із перших 200 розмірів вибірки. На тридцяти прогонах:

```
Distribution(runs=30, mean=480, p95=400, worst=1600)  tail_ratio 0.83
частка прогонів, гірших за p95: 6.7 %
```

`tail_ratio < 1` читається як «хвоста немає». Модуль, що існує рівно щоб показати хвіст, ховав
його — а перевірка стояла на ста прогонах, тобто на щасливому числі, де `round` і `ceil`
збігаються.

**`total = 0.0` на частково спожитому стрімі.** Той самий дефект, який `measure.py` описує як
уже спійманий на `first_audio` («`None`, а не `0.0`. Нуль — хибне значення»), лишений у
сусідньому полі того самого типу. Розклад, прочитаний після першого фрагмента, показував
«усього 0 мс» поруч із непорожнім переліком кроків.

## Перевірки без зубів — сім штук

| Перевірка | Чому не ловила | Доведено |
|---|---|---|
| мікрофон лише після дії | `assert ... in after or ... in before` — права половина істинна для будь-якої сторінки зі слухачем подій | винесення `getUserMedia` на рівень модуля лишало зеленою |
| сеанс не лишає слідів | `assert forbidden not in source or forbidden == "wav"` — сторож, знерухомлений під власний код | `"wav"` є в `page.html` завжди |
| те саме | у переліку `write_bytes`, але не `write_text` | мутація «пише розпізнане через `write_text`» проходила наскрізь |
| сокет не має власних затримок | `... or "clock.sleep" in socket` — `clock.sleep` був у файлі завжди | `time.sleep(0.5)` не червонив |
| відсутня модель | `absent is None or absent == MISSING` — істинне завжди | гілка «моделі є» не виконувалась ніде, а вона й була зламана |
| двадцять прогонів дають одне число | чиста функція над детермінованим лічильником | мигтіння, від якого існує NFR-6, спостерігати не могла |
| конвеєр не читає системний годинник | греп по трьох іменах | `datetime.now()`, `time.time_ns()` проходили |

Виправлено кожну. Мікрофон — позиційним включенням у тіло `start()`; сховище — переліком без
винятків плюс `write_text`; затримки — AST-розбором; відсутня модель — параметром із переліком
модулів, тож обидві гілки виконуються; детермінізм — двома одночасними стрімами замість
двадцяти послідовних; годинник — розбором **імпортів** замість переліку слів.

## Навчальні тексти суперечили коду

**Вправа 5 не компілювалась.** Мутація підставляла `CHUNKS_SENTINEL`, якого в репозиторії
немає. Усі пʼять «червоних» були `NameError`:

```
FAIL  stream: час до першого звуку щонайменше вдвічі менший за батчевий
--- NameError: name 'CHUNKS_SENTINEL' is not defined
```

Жодного ассерту досягнуто не було, а проза стверджувала механізм, якого не сталося. Це
дослівний повтор двох уроків `PLAYBOOK.md §5`, записаних раніше цим самим репозиторієм.

Замінено на `enumerate(list(think_chunks(...)))` — один виклик `list()`, що перетворює стрімінг
на батч. Компілюється, ламає рівно ту властивість, про яку каже проза, і це найчастіша помилка
в реальному коді.

**`mutate.py s07 --expect` був червоний: РОЗБІЖНОСТЕЙ 3.** Зайву червону в усіх трьох випадках
давала `check_the_lesson_numbers_match_the_measurements` — перевірка про **прозу**, що
перераховувала числа зі вже зламаного коду. `require_intact_source` було застосовано лише до
перевірки рядків. Тепер — до всіх шести модулів, які вона міряє.

**«Відношення падає з 3.5x до 1.6x»** — заміряно 1.69, тобто 1.7. Виправлено; те саме число
з двома знаками тепер названо в чеклісті, бо саме його читач побачить у повідомленні.

**«Марна робота, названа у трейсі»** — трейсу в етапі не було взагалі.

## AC-04: жодного прогону не відбувалось

Критерій каже «сто прогонів на однакових даних **із розкидом затримок**». Розподіл набирався
літералами `[400.0] * 90 + [1600.0] * 10`, а демо друкувало «прогонів: 100» для списку,
набраного руками — на етапі, теза якого «оптимізувати можна лише те, що виміряно».

Підроблений годинник розкиду не дає **за побудовою**, і це його чеснота. Тому розкид тепер
вносить модель: `latency(run)` — чиста функція номера прогону, двоярусний хвіст. Сто справжніх
прогонів дають середнє 1859 мс, p95 3824 мс, найгірший 6824 мс; повторний прогін дає ті самі
сто чисел.

Один ярус дав би p95, що дорівнює найгіршому, — і різниця між «майже найгірший» і «найгірший»
зникла б саме там, де етап її показує.

## Решта виправленого

- **`synchronous()` і `prefetched()` міряли різні величини під одним іменем.** Синхронний шлях
  не спав часу роздуму, тож наївне порівняння двох `.millis` показувало prefetch **повільнішим**
  на 250 мс. Обидва споживачі зшивали різницю ззовні руками.
- **Відкинутий prefetch чекав на інструмент**, який рядком нижче оголошувався марною роботою.
  Обидві точки виклику були підібрані так (500 проти 600), що різниці не було видно.
- **Порожня відповідь моделі давала «до першого звуку: 0 мс»** — найкращу можливу затримку для
  прогону без звуку.
- **Сторінка:** мікрофон не звільнявся при помилці після дозволу, і кнопка лишалась навіки
  вимкненою; не було `onclose`/`onerror`, тож індикатор показував намір, а не стан; гілка
  `kind === "audio"` була недосяжна, а `message.note` стирав вердикт при кожному розкладі;
  таблиця малювала повторювані назви кроків без рядка суми.
- **`RealClock.sleep` блокував event loop** — дві розмови серіалізувались. Крок конвеєра тепер
  іде в потік.
- **`run.py --real` не передавав годинника у сцени** — прапорець змінював лише банер.
- **Докстрінг `pipeline.py` називав типи, яких функції не повертають** (`-> Spoken`,
  `-> Iterator` замість `Reply` і `Stream`) — саме там, де ADR-0003 будує урок на тому, що
  «різниця видима в типі».
- **`Stream.chunks` після часткового проходу віддавав хвіст** — мовчазна половина відповіді.
- **README казав «перевірок три»** там, де їх чотири.
- **Числа сторінки не могли збігтися з прогоном:** тривалість виводилась із довжини
  **стиснутого** opus (`len(chunk)/32_000` → 25 мс замість 200). Сторінка тепер називає
  тривалість кадру сама, а її обіцянка змінена на чесну: збігається **структура** розкладу.

## Що лишається неперевіреним — свідомо

- **AC-07** (`НЕ ПЕРЕВІРЕНО`): звук на справжньому мікрофоні зі справжніми моделями. Ваг і
  мікрофона в автора немає. Сокет тепер запускається перевіркою (AC-07c) — без звуку, але з
  повною розмовою; неперевіреним лишається саме звук.
- **`real.py`** написано, але не виконано. Найслабше місце етапу, назване в обох README, у
  `sad.md` §11 і у власному докстрінгу файлу.
