## The main finding: e2e never once looked at the trace

```python
def e2e(case: Case, judge: Judge) -> Verdict:
    scored = judge.score(case.task, case.answer, case.expected_answer)
```

`case.answer` is the **description** of the case, not what the agent said. `trajectory.answer()`
existed and was called by **no** level: its only readers were `online.py` and `blind_spots`.

The consequence is measurable: drop the closing step from a case — the trace then holds no
answer at all, and e2e calmly says **"passed, score 3"**. The judge is scoring text that never
made it into the trace.

The second one is worse. The AC-03 check, "the same answer, different paths", compared:

```python
assert straight.by_level(E2E).state == lucky.by_level(E2E).state
```

Both cases carry the **same string** in `case.answer`, and both go through one and the same
deterministic judge. That is an identity impossible to break — exactly the shape AC-01b warns
against one level over.

**Fixed.** `e2e(case, trajectory, judge)` takes the answer from the trace; no answer →
**unscored**, symmetrically to the component level. The consequences are visible in the report:
e2e became `12 / 7 / 2` instead of `12 / 9 / 0`, and judge calls 19 instead of 21, because the
judge is no longer called on the two traces with no answer. Nobody pays for missing data.

Separately, `Trajectory.answer()` had to be restricted to model steps: tool results carry a
`text` field too, so without that the "last answer" became the last line of any origin
whatsoever — against the rule that "e2e is about the last **answer** and about nothing else".

## The `--real` mode was broken in three ways

The very mode by which the lesson promises the reader a way to repeat the proof against a real
model.

**The score parser collected every digit in the string.** Measured:

```
'8'                  -> 8      correct
'8/10'               -> 10     the scale became the score
'score: 3 out of 10' -> 10     the three became a ten
'0 out of 10'        -> 1      the zero became a one
```

The prompt names the scale itself ("Give a score from 0 to 10"), so repeating it back is the
likeliest shape of an answer. A stage whose thesis is "do not trust the instrument" was itself
passing off a broken instrument as a working one.

**The verdict parser looked for a substring in a fixed order.** `"the first is worse, the second
wins"` gave `first`. That is not merely a wrong verdict: `position_sweep` counts such cases as
**flips** — the detector was reporting a bias produced by its own parser, on a judge that had
none.

**The banner was chosen by the flag rather than by the presence of a key.** `--real` with no
provider printed "The judge is real: the numbers will flicker", after which everything became
`UNSCORED`, while the first line had promised the opposite.

**One cause is common to all three: `ModelJudge` never ran once.** It was not even in the import
list of `check.py`; both fake judges raise `Unavailable` themselves. A file that is only read is
a file that is not run (PLAYBOOK §5, the same lesson that cost stage 7 a live mode that did not
work).

**Fixed:** both parsers either accept the exact shape or hand back the third state; a check
`FAILURE · judge model: the verdict parses exactly or it does not parse` was added, and it runs
the **real** `ModelJudge` with a substituted transport.

## The eighth scene never ran

```python
found = Path("traces") / f"{name}.jsonl"     # traces/s01.jsonl, traces/s06.jsonl
```

`shared/trace.py` writes `traces/<date>.jsonl` — the name `s01.jsonl` does not exist and never
did. Both branches printed "there is no trace", and the answer to AC-12 stood below them as
**hardcoded prose**. Meanwhile `exercises.md` was asking the reader to run the stages and
reproduce it — an instruction that punishes obedience.

**Fixed:** the scene reads everything out of `traces/`, groups it by the `stage` meta field and
prints what it measured. One line per **file**, not per stage inside it: the first version of
the fix showed the same number three times as though it were three different measurements.

## AC-12: the answer was wrong, and the check never reconciled it

The wording "the stages mark a run with **four** different fields (`scenario`, `phase`,
`scene`, `trace_ref`), and **two** do not mark it at all" stood in five places and was wrong
twice over:

- **Stage 4's `phase` is not a run key.** It is the phase of the **failure** (`startup`,
  `parse`), set by `describe_failure`; on the happy path it is `None`. A field that appears only
  when something broke distinguishes breakages, not runs.
- **It is not two stages without a key, but four:** 2, 3, 4 and 7. ADR-0008 skipped stage 7 in
  its summary table, even though **that same ADR's own measurement block** lists it.

A number describing the absence of measurement was itself a guess.

**Fixed:** `trajectory.survey_run_keys()` parses the **tracer calls** in the sources (AST, not
grep: stage 7's `whole(run=run)` is a function parameter, and grep read it as a trace field),
and the check reconciles the result against the lesson's prose. Measured: **3 fields, 4 stages
without a key**.

## Six checks that could not go red

| Check | Why it caught nothing | Proof |
|---|---|---|
| privacy (AC-07b) | looked at `Watch` — counters and constant literals; no mutation would ever put text there | the assert is true **by construction** |
| the same one (second half) | grepped `"user request" in watch.__doc__` | swapping the default leaves the docstring untouched |
| the make-up of the suite in the demo | `str(9) in output` on output full of digits | under exercise 10's mutation `"2" in output` passes too |
| "there is no combined score" | looked for three hand-picked phrases that `render()` never prints | no mutation produces such a line |
| online writes nothing | a grep for `"trace_run"`, `"write_text"`, `"open("` | circumvented via `os.replace`, `json.dump(handle)` |
| reading through `shared.trace` | `"from shared.trace import iter_steps" in reader` — the presence of a substring | a shape that reddens on a docstring; `code_mentions` was quoted nearby in the same file and never used |

**Fixed:** the negations moved onto `code_mentions` (AST, which does not see docstrings), the
identity onto `extract.__globals__["iter_steps"] is shared_iter_steps`, privacy onto a
**written report** with a secret in the `reason` field, the signature onto `inspect.signature`.

And the leak was real: `levels.component` copied `step["reason"]` — free text — straight into
the verdict's reason, and `render` printed it into the report. Now the **name** of the field is
printed (`tool`, `node`), not its value.

## Three more mistakes that made the report greener

- **`status` was still a flag for edge-ness.** `dataclasses.replace(case, status="whatever").edge`
  gave `True` — that is, a suite of twenty-one happy paths could be switched on by a single
  line, exactly the scenario AC-10 names as the reason to drop the label. `edge` is now read
  **exclusively** from `acts`, and a check empties every other field in turn and demands that
  edge-ness not change.
- **The closed list of "unavailable" was open.** `except Exception` turned a `ZeroDivisionError`
  in the harness into "unscored" — quiet green instead of a loud failure, against §8's direct
  promise ("a new cause will read as a failure — deliberately loud").
- **`blind_spots` declared blindness to a check that did not exist.** The line "an empty answer
  cannot be caught" asserted that the check existed and was switched off by missing data; in
  `cheap()` there was no such check at all. Now there is — under the same guard.

## The demo cost twice what it reported

`main()` ran both bias sweeps for `report.findings`, and then `scene_position` and
`scene_length` ran them **a second time with the same judge**. The counter was read before the
sweeps, so the report printed `judge calls: 21` when there had been **41**. With `--real` that
is twenty extra paid calls on every run — and straight against ADR-0004's driver.

## NFR-6b promised a branch that did not exist

"With a key the flicker check becomes `NOT EVALUATED` — the same check, a different branch"
stood in the spec and in both READMEs. `grep NotVerified stages/s08_eval/*.py` returned nothing.
Now the branch exists.

## Two fixes outside the stage

- **`shared/trace.py`: a truncated tail no longer breaks reading.** The file is appended to
  without rewriting (ADR-0009), so a process killed mid-write naturally leaves a truncated line.
  A reader that crashes on it makes the whole trace unusable for the sake of its last line — and
  the trace is needed precisely when something killed the process. The eighth scene now reads
  the reader's own files, so this became mandatory.
- **No check exercised the `TRACE_SINK` message** — and that is exactly why its previous wording
  lived on carrying a factual error, citing a stage 6 ADR that never took that decision. Two
  checks were added to `shared/check.py`.
