## Findings

Duplicates between the reviewers were merged; the higher of the two severities was taken.

### MAJOR-1 · The confirmation gate is blanket, not per-event
- **Where:** `stages/s01_agent_loop/loop.py:103-109,146-153`
- **Concerns:** AC-04, stage ADR 0002, `README.md:219`
- **Problem:** the confirmation applies to the whole run. Reproduced: a model response with two
  `initiate_return` calls in an unconfirmed run is blocked at the first, and the Learner never
  learns about the second; a confirmed run executes **both**, including the one the user never saw.
- **Why it matters:** the lesson promises, word for word, "the run shows exactly what would have
  happened. Confirming blind is not confirmation". The code does exactly blind confirmation.
- **Resolution:** FIX. Block the step as a whole, listing every irreversible call in it.

### MAJOR-2 · There is no way to confirm from the CLI
- **Where:** `stages/s01_agent_loop/run.py:78,116` against `loop.py:151`
- **Concerns:** AC-04, `sad.md` `target_surfaces: [cli, …]`
- **Problem:** the message says "run it again with confirmation", but `main()` does not read
  `argv`. `confirmed=True` can only be passed from Python. The Learner cannot follow the
  instruction.
- **Resolution:** FIX. A `--confirm` flag.

### MAJOR-3 · Non-object arguments kill the run
- **Where:** `stages/s01_agent_loop/validate.py:68,73,77`
- **Concerns:** AC-03 ("the run **does not die** with a technical error"), `sad.md` §8
- **Problem:** `validate_arguments` assumes a `dict`. Valid JSON `null` / `42` / `"Kyiv"` /
  `[1,2]` produces a `TypeError` or an `AttributeError` that escapes `run_agent`.
- **Resolution:** FIX. A type check on entry.

### MAJOR-4 · `additionalProperties` fails open
- **Where:** `stages/s01_agent_loop/validate.py:72` → `loop.py:155`
- **Concerns:** AC-03, stage ADR 0003
- **Problem:** the "unknown fields" branch is switched on only by whoever wrote the schema. A
  schema without that key lets extra arguments through into `tool.func(**checked)` → a `TypeError`
  escapes. Reproduced. Exercise 2 asks the reader to add a tool — the simplest schema will be
  exactly the one without the key.
- **Why it matters:** a guard that works only when the schema's author remembered to switch it on
  is not a line of trust but an agreement. Fail-open on a line of trust.
- **Resolution:** FIX. Invert it to fail-closed.

### MAJOR-5 · An exception from a tool function kills the loop
- **Where:** `stages/s01_agent_loop/loop.py:155`
- **Concerns:** `sad.md` §8, stages 6 and 10 inherit the pattern
- **Problem:** `tool.func(**checked)` is not inside a `try`. A tool that fails in the normal course
  of business (in production, an HTTP 500) kills the run; there is no `tool_error` step at all.
- **Resolution:** FIX. Symmetrically to `tool_rejected`: the step's result, not an exception.

### MAJOR-6 · Lesson item "What to break" №1 describes the opposite effect
- **Where:** `stages/s01_agent_loop/README.md:227-229`
- **Problem:** "remove `and not confirmed`" turns `if tool.irreversible and not confirmed` into
  `if tool.irreversible` — the gate starts blocking **always** rather than never. The demo does not
  pass `confirmed`, so the output does not change and the reader concludes they are looking in the
  wrong place.
- **Resolution:** FIX. Name the edit that genuinely switches the gate off.

### MAJOR-7 · "Exactly one check goes red" is untrue, and the reason is wrong
- **Where:** `stages/s01_agent_loop/exercises.md:34`, `CHECKLIST.md:17`; root cause —
  `check.py:153-155`, `run.py:48`
- **Problem:** with the gate switched off **two** checks fail, and both with
  `FakeLLMError: script exhausted` — that is, **before** the `assert calls == []`. The fake's
  script has one step; the moment the gate stops cutting the run short, the loop goes to the model
  a second time.
- **Why it matters:** a test with the right verdict and the wrong cause. It passes a mutation check
  (red when the code is broken), so it looks like a test with teeth — but it goes red because the
  script ran out, not because the invariant was violated. The author (that is, me) checked the
  mutation at T4, saw "1 of 16 failed" and did not look at **what exactly** it failed on.
- **Resolution:** FIX. Add the closing step to the script and reconcile the numbers in the texts.

## Consequence for the artefacts

## What this review proved about the process itself

Seven MAJOR findings out of seven were found by **clean context**, and not one of them was found
by the author, who had run his own mutation test beforehand and considered it proof. Two of them
directly refute statements the author made in the commit messages.

This is the argument for independent review in its strongest form: not "a fresh pair of eyes is
useful" but "an author structurally cannot see a certain class of defect in their own code, no
matter how many checks they write".
